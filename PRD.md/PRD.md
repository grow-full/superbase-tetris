## 1. 개요

### 1.1 목적
브라우저에서 바로 플레이할 수 있는 낙하형 블록 퍼즐 게임을 만든다. 플레이 점수는 Supabase에 저장해 랭킹으로 보여주고, 사용자는 게임에 대한 피드백을 남길 수 있다.

### 1.2 원본 요구사항 정리
| # | 사용자 요구사항 | 해석 / 정리 |
|---|---|---|
| R1 | 웹 기반 테트리스 | 설치 없이 브라우저에서 동작하는 낙하형 블록 퍼즐 게임 (10×20 보드, 4칸 블록 7종) |
| R2 | 점수를 Supabase에 저장 | 게임 오버 시 닉네임 + 점수를 Supabase DB에 저장하고 랭킹(리더보드)으로 조회 |
| R3 | 사용자 피드백 작성 | 피드백 작성 폼 + Supabase 저장. 목록 공개 여부는 확인 필요 (9장) |
| R4 | 배경음 + 효과음 | BGM 반복 재생, 이동/회전/착지/줄 제거/게임오버 효과음. 음소거·볼륨 조절 제공 |
| R5 | 그림자 효과 없음 | 블록이 떨어질 위치를 미리 보여주는 **고스트 피스(그림자) 미구현** |
| R6 | Vercel 배포 | GitHub 저장소와 연동해 push 시 자동 배포 |

### 1.3 지식재산권 관련 제약
- "TETRIS(테트리스)"라는 이름, 로고, 고유 디자인은 The Tetris Company의 상표다. 공개 배포하는 서비스이므로 **화면에 표시되는 게임 이름은 독자적인 이름**을 쓴다. 저장소 이름은 그대로 둬도 된다.
- 장르 메커니즘(낙하 블록, 줄 제거)은 쓰되, 색상 팔레트·UI·음악은 **오리지널**로 만든다.
- 이 게임과 널리 연관된 민요 "코로베이니키" 같은 곡은 쓰지 않는다. BGM은 직접 합성하거나 상업적 이용이 가능한 무료 음원을 쓴다.

## 2. 목표 / 비목표

### 2.1 목표
- PC 브라우저(Chrome, Edge, Safari, Firefox 최신 버전)에서 끊김 없이(60fps) 플레이

- 피드백 작성 흐름은 3단계 이내 (열기 → 작성 → 제출)
- `main` 브랜치에 push하면 Vercel이 자동 배포

### 2.2 비목표 (이번 버전에서 하지 않음)
- 고스트 피스(그림자) — 요구사항 R5
- 실시간 멀티플레이 / 대전
- 회원가입 및 소셜 로그인 (확인 필요, 9장)
- 서버 측 점수 검증(치트 방지) — 7.3 참고, 추후 과제
- 네이티브 앱

## 4. 기능 요구사항

### 4.1 게임 플레이 (F-GAME)
| ID | 기능 | 상세 | 우선순위 |
|---|---|---|---|
| F-GAME-01 | 게임 보드 | 가로 10 × 세로 20칸. 보드 위에 보이지 않는 생성 영역 2줄 | 필수 |
| F-GAME-02 | 블록 | 4칸 블록 7종 (I, O, T, S, Z, J, L). 종류마다 다른 색 | 필수 |
| F-GAME-03 | 블록 생성 | 7-bag 방식(7종을 섞어 한 묶음씩 꺼냄)으로 같은 블록이 계속 나오는 것을 방지 | 필수 |
| F-GAME-04 | 이동 | 좌/우 이동, 키를 누르고 있으면 반복 이동 (DAS 약 170ms, ARR 약 50ms) | 필수 |
| F-GAME-05 | 회전 | 시계/반시계 회전. 벽·바닥에 막히면 위치를 보정해 회전 (월 킥) | 필수 |
| F-GAME-06 | 소프트 드롭 | 누르는 동안 빠르게 낙하, 1칸당 1점 | 필수 |
| F-GAME-07 | 하드 드롭 | 즉시 바닥까지 떨어뜨리고 고정, 1칸당 2점 | 필수 |
| F-GAME-08 | 고정 지연 | 바닥에 닿은 뒤 0.5초 후 고정. 그 사이 이동/회전하면 시간 초기화 (최대 15회) | 필수 |
| F-GAME-09 | 줄 제거 | 가로 한 줄이 꽉 차면 제거하고 위쪽 블록이 내려옴. 짧은 제거 애니메이션 | 필수 |
| F-GAME-10 | 다음 블록 미리보기 | 다음에 나올 블록 3개 표시 | 필수 |
| F-GAME-11 | 홀드 | 현재 블록을 보관하거나 보관한 블록과 교체. 블록 하나당 한 번만 사용 가능 | 권장 |
| F-GAME-12 | 레벨 | 10줄을 지울 때마다 레벨 +1, 레벨이 오를수록 낙하 속도 증가 | 필수 |
| F-GAME-13 | 일시정지 | P / Esc 키로 일시정지·재개. 일시정지 중에는 보드를 가림 | 필수 |
| F-GAME-14 | 게임 오버 | 새 블록이 생성 위치에서 겹치면 종료 → 결과 화면 | 필수 |
| F-GAME-15 | 고스트 피스 | **구현하지 않음** (R5) | 제외 |

### 4.2 점수 규칙 (F-SCORE)
| 동작 | 점수 |
|---|---|
| 1줄 제거 | 100 × 레벨 |
| 2줄 제거 | 300 × 레벨 |
| 3줄 제거 | 500 × 레벨 |
| 4줄 동시 제거 | 800 × 레벨 |
| 소프트 드롭 | 1칸당 1점 |
| 하드 드롭 | 1칸당 2점 |

- 화면에 점수, 레벨, 지운 줄 수, 플레이 시간을 실시간으로 표시
- 로컬 최고 점수는 `localStorage`에도 저장 (오프라인일 때 대비)

### 4.3 조작 키 (F-INPUT)
| 키 | 동작 |
|---|---|
| ← / → | 좌우 이동 |
| ↓ | 소프트 드롭 |
| Space | 하드 드롭 |
| ↑ / X | 시계 방향 회전 |
| Z / Ctrl | 반시계 방향 회전 |
| C / Shift | 홀드 |
| P / Esc | 일시정지 |
| M | 음소거 전환 |

- 모바일 터치 조작 지원 여부는 확인 필요 (9장)

### 4.4 랭킹 / 점수 저장 (F-RANK) — Supabase
| ID | 기능 | 상세 | 우선순위 |
|---|---|---|---|
| F-RANK-01 | 닉네임 입력 | 게임 오버 화면에서 닉네임 입력 (2~12자). 마지막 닉네임을 `localStorage`에 기억 | 필수 |
| F-RANK-02 | 점수 저장 | 닉네임, 점수, 레벨, 줄 수, 플레이 시간을 `scores` 테이블에 저장 | 필수 |
| F-RANK-03 | 리더보드 | 상위 10명 (점수 내림차순, 동점이면 먼저 달성한 순) | 필수 |
| F-RANK-04 | 내 순위 표시 | 방금 저장한 점수의 순위를 강조 표시 | 권장 |
| F-RANK-05 | 기간별 랭킹 | 전체 / 이번 주 / 오늘 탭 | 선택 |
| F-RANK-06 | 오류 처리 | 저장 실패 시 안내 메시지 + 재시도 버튼. 게임 진행에는 영향 없음 | 필수 |

### 4.5 피드백 (F-FB) — Supabase
| ID | 기능 | 상세 | 우선순위 |
|---|---|---|---|
| F-FB-01 | 피드백 작성 | 닉네임(선택), 만족도 별점 1~5, 내용(1~500자) 입력 후 제출 | 필수 |
| F-FB-02 | 카테고리 | 버그 / 개선 제안 / 칭찬 / 기타 중 선택 | 권장 |
| F-FB-03 | 제출 결과 | 성공/실패 안내 메시지. 연속 제출 방지 (클라이언트에서 30초 쿨다운) | 필수 |
| F-FB-04 | 피드백 목록 | 최신순 목록 공개 여부는 확인 필요 (9장) | 확인 필요 |
| F-FB-05 | 진입 경로 | 메인 화면과 게임 오버 화면에 "피드백 남기기" 버튼 | 필수 |

### 4.6 사운드 (F-SOUND)
| ID | 기능 | 상세 | 우선순위 |
|---|---|---|---|
| F-SOUND-01 | 배경음(BGM) | 게임 중 반복 재생. 일시정지하면 멈추고 재개하면 다시 재생 | 필수 |
| F-SOUND-02 | 효과음 | 이동, 회전, 하드 드롭, 고정, 줄 제거(1~3줄), 4줄 제거, 레벨 업, 홀드, 게임 오버 | 필수 |
| F-SOUND-03 | 음소거 / 볼륨 | BGM과 효과음 볼륨을 각각 조절, 전체 음소거 버튼. 설정은 `localStorage`에 저장 | 필수 |
| F-SOUND-04 | 자동재생 정책 | 브라우저 정책상 사용자가 처음 클릭/키 입력한 뒤에 오디오 시작 ("시작" 버튼에서 초기화) | 필수 |
| F-SOUND-05 | 음원 출처 | Web Audio API로 직접 합성하거나 상업적 이용 가능한 무료 음원 사용. 출처는 README에 기록 | 필수 |

### 4.7 화면 구성 (F-UI)
1. **메인 화면**: 게임 이름, 시작 버튼, 랭킹 보기, 피드백 남기기, 조작법, 사운드 설정
2. **게임 화면**: 보드(가운데), 홀드(왼쪽), 다음 블록·점수·레벨·줄 수(오른쪽), 일시정지·음소거 버튼
3. **게임 오버 화면**: 최종 점수, 닉네임 입력 → 저장, 리더보드, 다시 하기, 피드백 남기기
4. **리더보드 화면 / 모달**
5. **피드백 모달**

- 반응형: 데스크톱 우선, 화면 너비 768px 이하에서는 세로 배치
- 접근성: 키보드만으로 모든 메뉴 조작 가능, 버튼에 레이블 제공

## 6. 기술 스택 (구현 기준)
| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | 없음 (ES 모듈 그대로 제공). Vercel에서 `scripts/build.mjs`가 `dist/` 복사 + `config.js` 생성 | 개발 PC에 Node.js가 없어도 바로 실행·수정 가능 |
| 언어 | JavaScript (ES2022 모듈) | 빌드 없이 브라우저에서 바로 실행 |
| UI | 순수 HTML/CSS + Canvas 2D + `<dialog>` | 게임 하나와 모달 몇 개라 프레임워크가 불필요, 번들이 가벼움 |
| 오디오 | Web Audio API (배경음·효과음 직접 합성) | 지연 없는 효과음, 볼륨 개별 제어, 음원 저작권 문제 없음 |
| 백엔드 | Supabase REST API를 `fetch`로 직접 호출 | 요구사항 R2, R3. 라이브러리 없이 필요한 호출(추가·조회·개수)만 사용 |
| 테스트 | Node 내장 `node:test` | 추가 패키지 불필요 |
| 배포 | Vercel (GitHub 연동) | 요구사항 R6 |

> 초안의 Vite + TypeScript 안은 개발 PC에 Node.js가 없어 위와 같이 바꿨다.

## 7. 데이터 설계 (Supabase)

### 7.1 테이블
**`scores`**
| 컬럼 | 타입 | 제약 |
|---|---|---|
| id | uuid | PK, 기본값 `gen_random_uuid()` |
| nickname | text | NOT NULL, 2~12자 |
| score | integer | NOT NULL, 0 이상 9,999,999 이하 |
| level | integer | NOT NULL, 1 이상 |
| lines | integer | NOT NULL, 0 이상 |
| duration_sec | integer | NOT NULL, 0 이상 |
| created_at | timestamptz | 기본값 `now()` |

인덱스: `(score desc, created_at asc)`

**`feedback`**
| 컬럼 | 타입 | 제약 |
|---|---|---|
| id | uuid | PK |
| nickname | text | NULL 허용, 최대 12자 |
| category | text | `bug` / `idea` / `praise` / `etc` |
| rating | smallint | 1~5 |
| content | text | NOT NULL, 1~500자 |
| created_at | timestamptz | 기본값 `now()` |

### 7.2 RLS(행 단위 보안) 정책
| 테이블 | anon 조회(SELECT) | anon 추가(INSERT) | 수정 / 삭제 |
|---|---|---|---|
| scores | 허용 | 허용 (위 제약을 통과한 값만) | 금지 |
| feedback | 공개 목록이면 허용, 아니면 금지 | 허용 | 금지 |

### 7.3 알려진 한계 — 점수 조작
점수를 브라우저에서 계산해 보내므로 개발자 도구로 가짜 점수를 넣을 수 있다. 1차 버전에서는 DB 제약(최대값, 레벨·줄 수와 점수의 대략적인 일치 여부 확인)으로만 막는다. 필요하면 다음 버전에서 Supabase Edge Function으로 입력 기록을 검증한다.

### 7.4 환경 변수
| 이름 | 설명 |
|---|---|
| `SUPABASE_URL` | Supabase 프로젝트 URL |
| `SUPABASE_ANON_KEY` | Supabase 공개(anon 또는 publishable) 키 |

배포는 Vercel 프로젝트 설정 → Environment Variables에 등록한다 (빌드 때 `config.js`로 변환). 로컬은 `config.example.js`를 `config.js`로 복사해 값을 채운다 (git 제외).

## 8. 배포 (Vercel)
1. GitHub 저장소 `grow-full/superbase-tetris`를 Vercel에 연결
2. 빌드 설정은 `vercel.json`에 있음 (Build Command: `npm run build` / Output: `dist`)
3. 환경 변수 2개 등록 (7.4)
4. `main` push → 운영 배포, PR → 미리보기(Preview) 배포
5. Supabase 마이그레이션 SQL은 Supabase 대시보드 SQL Editor 또는 Supabase CLI로 적용

## 11. 완료 기준 (인수 조건)
- [ ] 7종 블록이 7-bag 순서로 생성되고 이동·회전·드롭·줄 제거가 정상 동작
- [ ] 고스트 피스가 표시되지 않음
- [ ] 레벨이 오르면 낙하 속도가 빨라짐
- [ ] BGM과 효과음이 재생되고 음소거·볼륨 조절이 됨
- [ ] 게임 오버 후 닉네임을 입력하면 점수가 Supabase `scores`에 저장되고 리더보드에 나타남
- [ ] 피드백을 제출하면 Supabase `feedback`에 저장됨
- [ ] anon 키로는 점수/피드백을 수정·삭제할 수 없음 (RLS 확인)
- [ ] Supabase가 응답하지 않아도 게임은 플레이 가능
- [ ] GitHub `main` push 시 Vercel에 자동 배포됨
